# Как изменения доезжают до пользователей

Тот же порядок, что и в `leaddrive-v2` (полный текст с историей — там же,
`docs/DELIVERY-ARCHITECTURE.md`). Действует одинаково для всех сессий: Claude,
Codex, любых будущих.

Владелец работает один и не читает диффы. От него требуется ровно две вещи: один
раз добавить ключ и перед релизом ответить «давай» на короткий список.

## Зачем это появилось

6 сентября 2026 года в `main` соседнего репозитория за день влилось восемь PR под
именем владельца. Четыре из них он не открывал — включая фичу на главной, которую
никто не заказывал. Защиты у ветки не было никакой. Зелёные тесты означают «то, о
чём подумал автор, работает»; они ничего не говорят о том, о чём автор забыл, и
тем более о том, нужна ли эта работа вообще.

## Слой 1. В `main` только через pull request

Прямой пуш запрещён правилом репозитория. Обязательными должны быть проверки
самого GitHub: две джобы `.github/workflows/acceptance.yml` — `acceptance` и
`fresh-install`. Этот workflow идёт на КАЖДОМ PR: без фильтров по путям, без
`types`, и ни одна из джоб не стоит за `if:`, `needs:` или матрицей. Поэтому
требовать их безопасно — PR не повиснет вечно в ожидании проверки, которая для
него не стартует. Path-фильтрованные workflow (презентации, релизные образы)
обязательными не делаются по другой причине: workflow, который не стартовал,
не публикует проверку вовсе, и PR мимо фильтра ждал бы её вечно. (Джоба,
пропущенная через `if:`/`needs:` внутри стартовавшего workflow, — это другой
случай: пропуск GitHub считает успехом, то есть такая джоба гейт не держит
вовсе — поэтому тест и запрещает `if:`/`needs:` у обязательных.)

Цена: **отменённый прогон — не успех.** Сессии здесь регулярно отменяли
«лишний» docs-only прогон acceptance (в журнале их двадцать); после записи
такой коммит не смержить, пока прогон не запустят заново (~7 минут). Это
действует и сегодня. Отменять можно прогон того коммита, на котором мержиться не
собираешься. (В журнале есть и четыре коммита с отменённым `agent-review`, но та
проверка удалена и обязательной не была — на мерж её отмена не влияла.)

Настраивается не руками, а скриптом `scripts/ci/configure-main-protection.sh`.

**Записано 2026-11-01.** До этого дня на GitHub у `main` была обязательна одна
проверка — `agent-review`, — то есть мерж не держало ничто: ИИ-ревьюер без
ключа и при сбое API зелёный по построению, и здесь он был зелёным именно так
почти на каждом PR с #3 по #34 (Anthropic 400, insufficient credit). Из его 112
прогонов до записи красными были два, и оба не читали диф, а отказались от него
по размеру (PR #2 — 3 471 359 байт, PR #3 — 404 283 байта). Теперь обязательны
ровно две джобы `acceptance.yml`, привязанные к приложению GitHub Actions
(`app_id` 15368, то есть статус того же имени из другого источника не считается),
требование pull request и `enforce_admins` на месте. Сверить, ничего не
отправляя: `bash scripts/ci/configure-main-protection.sh --check` — `RESULT:
match`, код 0 (прочитано живьём 2026-11-01).

> ⚠️ **Старые копии скрипта пишут защиту без сверки.**
> В ветках и воркитри, отрезанных до правки 2026-10-31 (признак: в файле скрипта нет
> слова `--apply`), лежит прежний скрипт. Каждый его запуск — запрос на запись,
> без сверки: без аргументов запрос уходит в одноимённый репозиторий прежнего
> аккаунта (`rashadrahimov/…`), а с аргументом `rashadoni/…` — сюда, и тогда, по
> описанию API GitHub, снимает требование pull request. Не запускать.

Одобрения ревьюера не требуются: владелец работает один, и правило, которое
некому выполнить, останавливает доставку вместо того, чтобы её защищать.
`enforce_admins` включён — аварийного выхода нет, и это осознанно: мержить
красное не может никто, включая владельца.

## Слой 2. PR разбирает сессия, которая его не писала

Диф читает агент без заинтересованности в этом коде: он не выбирал решение и не
устал его защищать. Он сверяет изменение с тем, что задача требовала, ищет
дефекты и пишет разбор в PR — комментарием или описанием, так, чтобы он остался
рядом с кнопкой мержа, а не в чьей-то переписке.

**Проверки в CI у этого слоя нет, и это решение владельца (1 ноября 2026).**
Раньше была — `agent-review.yml` отдавала диф Anthropic API. Её удалили вместе со
скриптом `.github/scripts/agent-review.mjs`, потому что проверка, которая зеленеет
на своём же сбое, хуже отсутствующей: без ключа и при ошибке API она проходила по
построению, и ровно это здесь и происходило. Почти на каждом PR с #3 по #34, а
затем снова 1 ноября, Anthropic отвечал `400` — «Your credit balance is too low
to access the Anthropic API» (последний раз прочитано в прогоне 41349728232). Из
её 112 прогонов до записи защиты красными были два, и оба не читали диф, а
отказались от него по размеру. То есть галочка стояла зелёная, диф не читал
никто, а сессия, которая смотрела только на галочку, видела «разобрано».

Поэтому разбор здесь — работа сессии, и видно его по тому, что написано в PR, а
не по цвету проверки. Правило простое и проверяемое глазами: **своё же ревью не
считается** (правило 5 ниже). Если PR писала одна сессия, разбирает другая; если
разбора в PR нет, значит его не было.

Возвращать ИИ-ревьюера обязательной проверкой нельзя никогда — это решение
владельца от 2026-09-11 для всех его репозиториев. Тест
`scripts/ci/tests/test_main_protection_script.py` падает, если в обязательных
проверках оказывается что-то кроме джоб `acceptance.yml`.

## Слой 3. Прод

Всё, что уже построено в этом репозитории для выкладки: сборка, проверка здоровья,
откат. Слой 2 его не заменяет и не ослабляет.

## Слой 4. Слово владельца

Единственное, чего машина не может: «я такого не заказывал». Перед мержем того,
что увидит пользователь, показать короткий список — по одной строке на изменение,
человеческим языком, без имён файлов — и дождаться «давай».

Список нужен только для видимого. Правки тестов, документации и внутренних
скриптов в него не попадают.

## Что обязан делать любой агент

1. Не пушить в `main`. Только PR.
2. Не мержить красное и не ослаблять проверку, чтобы пройти.
3. Не мержить, пока не зелены проверки `acceptance.yml` (`acceptance` и
   `fresh-install`). Других обязательных нет, и ИИ-ревьюера в CI больше нет
   совсем: проверка, зеленеющая на своём же сбое, удалена 1 ноября 2026 — см.
   слой 2.
4. Перед мержем видимого — список из слоя 4 и «давай».
5. Своё же ревью не считается.
