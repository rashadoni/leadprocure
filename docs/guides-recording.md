# Как переснять видео-подсказки разделов

У каждого раздела своя запись: `apps/web/public/guides/<ключ>.az.webm` плюс постер
`.az.png`. Карта «маршрут → ключ» — `apps/web/src/guides.ts`, сценарии и комбайн —
`scripts/produce-guides.mjs`. Записи **только азербайджанские** (решение владельца
01.11.2026): `Guide.tsx` просит `.az` при любом языке интерфейса.

## Где это можно запускать

**Не на Contabo.** Съёмка — это Docker-сборка образа API, живой стенд, браузерный прогон
18 разделов и около двух сотен запросов к синтезу речи. Правила хоста запрещают здесь
полные сборки, браузерные прогоны и установку зависимостей, и обходить их не нужно: это
ровно та работа, для которой есть Мак или ephemeral-воркер.

Нужна машина, где есть **Docker, Node 20+, pnpm 10.33.4**, и где не жалко ~10 ГБ под
образы и тома.

## Один раз на машине

```bash
git clone https://github.com/rashadoni/leadprocure.git && cd leadprocure
git lfs install && git lfs pull        # записи лежат в LFS, без этого придут указатели
pnpm install --frozen-lockfile
pnpm --filter web exec playwright install chromium
```

Ключи синтеза речи — в корневой `.env` репозитория (он в `.gitignore`, в git его нет):

```
AZURE_SPEECH_KEY=…
AZURE_SPEECH_REGION=…
GEMINI_API_KEY=…
```

Для азербайджанского нужен **`GEMINI_API_KEY`**: `ENGINE.az = 'gemini'` (решение
владельца — озвучка из Google AI Studio). У Azure азербайджанский голос тоже есть
(`az-AZ-BanuNeural`, включается `TTS_AZ=azure`), но на слух признан слабым. Можно положить
несколько ключей (`GEMINI_API_KEY2`, `…3`): при дневной квоте скрипт сам переходит к
следующему.

Модель по умолчанию — `gemini-3.8-flash-tts`, голос **Kore**, язык передаётся **явно**
северным `az-AZ`. **И модель, и голос выбрал владелец на слух** 01.11.2026, сравнив три
пробы одной и той же азербайджанской фразы (3.8-flash, 3.8-flash-lite, 2.5-preview). Менять
их без того, чтобы дать ему послушать замену, нельзя. Язык задавать обязательно: Google перечисляет азербайджанский дважды, и
южный (иранский) — другая норма и другое письмо, для Баку он прозвучит неправильно.
Модель меняется через `GEMINI_MODEL`; учтите, что 3.8 отвечает контейнером `audio/wav`, а
2.5-preview — сырым L16, и скрипт различает это сам.

### Сначала проба, потом 18 записей

Голоса Gemini не привязаны к языку — один голос говорит на всех, и как он звучит именно
по-азербайджански, из документации не узнать. Поэтому **сначала одна короткая проба**, и
дать её послушать владельцу:

```bash
FORCE=1 DEMO_ISOLATED=1 DEMO_PG_CONTAINER=leadprocure-demo-pg DEMO_API_CONTAINER=leadprocure-demo-api DEMO_API=http://127.0.0.1:3200 node scripts/produce-guides.mjs http://localhost:5173 az sup-verification
```

Это самый короткий раздел (6 сцен). Голос и модель уже одобрены на пробах, так что проба
нужна не для выбора голоса, а чтобы увидеть всю цепочку целиком на одном коротком
разделе: встал ли стенд, попадает ли голос в кадр, не видно ли строки подсказки, нет ли
мёртвых пауз. Если что-то не так — чинить до того, как уйдут остальные семнадцать.

## Съёмка

```bash
bash scripts/demo-stand.sh
```

Скрипт поднимает одноразовый стенд, прогоняет миграции, сеет учётки и наполняет
демо-историю **по-азербайджански** (`DEMO_LANG=az` — сценарии кликают по названиям вида
«Tender: noutbuk və monitorlar», на другом языке эти клики промахиваются), затем печатает
две команды. Веб-фронт поднимается отдельно, потому что адрес API вшивается на сборке:

```bash
VITE_API_BASE_URL=http://127.0.0.1:3200 pnpm --filter web dev
```

```bash
FORCE=1 DEMO_ISOLATED=1 DEMO_PG_CONTAINER=leadprocure-demo-pg DEMO_API_CONTAINER=leadprocure-demo-api DEMO_API=http://127.0.0.1:3200 node scripts/produce-guides.mjs http://localhost:5173 az
```

`FORCE=1` обязателен для пересъёмки: без него скрипт **пропускает** разделы, у которых
файл уже есть (это поведение «продолжить прерванный прогон»). Один раздел — так:
`… node scripts/produce-guides.mjs http://localhost:5173 az buyer-budgets`.

После прогона стенд убрать: `bash scripts/demo-stand.sh down`.

## Что проверить глазами, прежде чем коммитить

Записи длинные и их 18, поэтому смотреть выборочно, но обязательно:

1. **Строки подсказки нет в кадре.** Скрипт прячет `[data-help-video-widget]`, чтобы
   подсказка не попала в запись самой себя. Если строка видна — селектор разошёлся с
   разметкой `Guide.tsx`.
2. **Нет мёртвых пауз.** Сцена, чьи действия длиннее озвучки, пишет в лог
   `⏱ <ключ>/az сцена N: действия дольше озвучки на Nс`. Логи прогона смотреть целиком.
3. **Курсор не стоит на месте всю сцену.** Значит селектор не нашёлся: такие промахи
   скрипт печатает как `(<ключ>/az: <сообщение>)` и идёт дальше.
4. **Постеры.** `<ключ>.az.png` снимается до появления курсора; он красит первый кадр
   внутри окна плеера. Плавающей миниатюры на странице нет — карточку убрали в PR #73.
5. **Голос попадает в кадр**, а не отстаёт: озвучка начинается на границе сцены, курсор
   идёт следом с задержкой `LEAD = 650 мс`.

## Размер: решить до коммита

Записи в Git LFS (`.gitattributes`), поэтому пак репозитория маленький. Но каждая полная
пересъёмка 18 разделов — это ещё ~124 МБ в LFS-складе (на 01.11.2026 склад был 445 МБ,
241 объект). Бесплатный лимит GitHub — 1 ГБ склада и 1 ГБ трафика в месяц, и
`fresh-install` в CI тянет LFS на каждом прогоне. Две-три пересъёмки — и упираемся.
Варианты: чистить историю LFS или вынести записи в объектное хранилище и отдавать
веб-контейнером. Это решение владельца, и его лучше принять **до** того, как в LFS
уедет очередная сотня мегабайт.

## Правила, которые нельзя нарушать

- **Один контекст браузера на роль.** Переиспользование одного `storageState` между
  контекстами повторно предъявляет провёрнутый refresh-токен и срабатывает защита от
  кражи сессии. Это сделано нарочно.
- **Длину задаёт рассказ, а не таймер.** Сначала измеряется озвучка каждой сцены, потом
  блок держится ровно столько. Не переделывать в «пауза N секунд»: беты внутри сцены —
  доли озвучки (`h.holdUntil(0.4)`), поэтому фраза другой длины всё равно попадает.
- **`demo-fill.mjs` только на одноразовый стенд.** Он зовёт `assertDemoTarget` на самом
  верху модуля, без флагов, и отказывает всему, что не помечено как disposable.
  `infra/DEPLOY.md` запрещает демо-сид на проде первой же строкой.
- **Селекторы сценариев**: `data-testid` → собственный текст заголовка или кнопки →
  позиционный только там, где порядок колонок закреплён браузерными тестами. Перед
  правкой сверять текст со словарём `az` в `apps/web/src/i18n.tsx`, а порядок ячеек
  читать из JSX, а не угадывать.
- **Действия в сценариях не должны менять стенд.** Все 18 записей снимаются против одного
  стенда, и след одной записи виден в остальных: заблокированный в клипе про поставщиков
  поставщик останется заблокированным в клипе про тендеры, а «прочитать все уведомления»
  опустошит панель в клипе про панель. Поэтому действия выбраны такие, что следа не
  оставляют: раскрытия (диалог рейтинга открыть и **отменить**, редактор политики открыть и
  **закрыть**) и переходы последней сценой. Если понадобится действие, меняющее состояние,
  — заводить под него отдельную запись и отдельные данные, а не трогать те, что показывают
  другие разделы.
- **Логистика без действия намеренно**: на странице ноль кнопок, хронологию ведёт
  поставщик у себя. Не «починять» выдуманным нажатием.

## Статус оснастки

`infra/docker-compose.demo.yml` и `scripts/demo-stand.sh` написаны 01.11.2026 по
исходникам `scripts/demo-target.mjs`, `infra/docker-compose.yml` и
`infra/docker-compose.prod.yml`, но **ни разу не запускались**: на Contabo это запрещено.
Проверено без запуска — `docker compose config` разбирает файл, `bash -n` проходит, и
главное: `assertDemoTarget` на разобранном определении стенда **принимает** его и при этом
по-прежнему отказывает прод-адресу, чужому порту, снятому флагу изоляции и контейнеру без
метки. То есть контракт сходится; первый живой прогон всё равно может потребовать правки
(вероятные места — сборка образа MinIO из `infra/storage` и `pnpm --filter api seed`
внутри контейнера).
